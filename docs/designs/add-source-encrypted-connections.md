## Problem Statement

The station lists email, Slack, Obsidian, db, and MCP, but adding a live one still means editing `.env` and `station.config.ts`. A SaaS or non-technical user will not do that. They need Add source: pick a kind, Sign in when the platform allows it, or paste the fields that kind requires. Multiple emails. Secrets encrypted at rest. Connecting must never send.

## Demand Evidence

Founder-as-user. Quote: "I need to be able to connect with multiple email through adding the credentials or signing in and authenticating using auth." Status quo chosen: keep the example mailboxes and almost never add a live one. No outsider has bounced on FIRST_RUN.md yet. This is a door the founder refuses to walk through, not proven paid demand.

## Status Quo

Two fixture mailboxes in `station.config.ts`. IMAP/SMTP and `GOOGLE_OAUTH_*` in `.env`. Slack/Obsidian/db/MCP are config rows only. Approved kit already specified `./data/tokens/{credentialsKey}.json` + AES-256-GCM; the cockpit never writes them.

## Target User & Narrowest Wedge

User zero: the founder. First paid shape: a founder/operator with more than one Gmail. Wedge: Add source on Channels, every kind, each save a live encrypted connection. Email Sign in with Google plus paste IMAP/SMTP. Other kinds collect their fields the same way.

## Constraints

- Throw only `StationError`. Log only through `@station/observability`. Redact secrets and mail bodies.
- Browser never receives `STATION_MASTER_KEY` or plaintext tokens.
- Worker binds `127.0.0.1`. Cockpit proxies with the control token that never ships to the client.
- HITL Approve / Edit / Kill still owns send.
- One OCI image. `/data` volume. No OS keychain (already rejected in the kit design).
- Tests and evals before program code.
- Related kit design: `docs/designs/agent-zero-station-kit.md` (token files). This doc chooses a ledger table instead of files.

## Premises

1. Every kind has Add source. The form is the fields that kind needs, plus Sign in when the platform supports it.
2. Multiple rows per kind. Each row is a tenant key.
3. Email: Sign in with Google and/or paste IMAP/SMTP / app password.
4. Slack: bot token + workspace id this ticket (no Slack OAuth). Obsidian: vault path. db: URL only, always read-only. MCP: name + command + args.
5. `GOOGLE_OAUTH_CLIENT_ID` / `SECRET` stay in `.env` (the station's Google app). User mailbox tokens do not.
6. Connecting does not send.
7. No Nylas/Unipile. We store and refresh tokens.

## Approaches Considered

### Approach A: Token-file vault + Add wizard
Ruled out in-session: file-per-mailbox has no rotation seam and is a weak SaaS spine. Rejection: user chose the table.

### Approach B: Connections table in the ledger
Chosen. Encrypted envelope columns. Queryable. `keyId` is stored as `v1` only this ticket. Multi-user workspace tenants are later.

### Approach C: Hosted inbox API
Ruled out: we would not own `commitSend`, and a clone-anywhere kit would need their key.

## Recommended Approach

Ledger `connections` row + worker-only decrypt + cockpit Add source.

```
browser  /channels  Add source
   │  never talks to :19174
   ▼
cockpit :19173  proxy (control token server-side)
   │  GET/POST /connections, /oauth/google/*
   ▼
worker 127.0.0.1:19174  encrypt / decrypt / OAuth code exchange
   │
   ▼
Postgres connections  ciphertext only
   │
   ▼
email.useConnection(account)  decrypt, Gmail API or SMTP, drop plaintext
```

Google cannot reach the worker. Canonical callback is `GET /oauth/google/callback` on the cockpit (or Caddy in front of it). Cockpit `GET /oauth/google/start` passes the request origin (or `STATION_PUBLIC_URL`) to the worker. `redirect_uri` is always `{origin}/oauth/google/callback`. Worker never puts `:19174` in the authorize URL. Local origin is `http://127.0.0.1:19173`.

Start/callback are dedicated cockpit routes that forward `Location` + status. They are not the JSON Approve `workerFetch`. They never log `searchParams`. They never put the control token in a 302. Worker exchanges the code, writes the envelope, cockpit 302s to `/channels/email/{id}`. Browser never calls `:19174`. Update `docs/DEPLOY.md` to this path (it still says `/oauth/callback`).

`return` after OAuth is allowlisted: `/`, `/channels`, `/channels/email`, `/channels/email/{id}`. Anything else is ignored.

PKCE `state` + verifier live in an in-memory Map on the single worker with a short TTL. No new table.

`POST /connections` accepts only paste envelopes per kind. OAuth envelopes are written only by the callback handler after code exchange. A client body with `transport: "gmail"` and a refresh token is `connections.invalid`.

### Schema

`migrations/002_connections.sql`. `applyLedgerMigration` must apply every `migrations/00*.sql` in order (today it only runs `001`). In-memory `getStation()` gets an equivalent map so T15 can run without Postgres.

SQL is snake_case (`tenant_id`, `key_id`, `created_at`, `updated_at`). Worker maps to camelCase. `CREATE TABLE IF NOT EXISTS`. `id` is a UUID on first insert, kept on upsert of `(kind, account)`.

Columns:

- `id` text PK
- `tenant_id` text = `account` in v1 (mailbox / Slack workspace / vault path / db label / mcp name). Workspace-level tenants are a later pack opt-in, not this table.
- `kind` text (`email` | `slack` | `obsidian` | `db` | `mcp`)
- `account` text
- `label` text
- `status` text (`pending` | `live` | `error` | `needs_reauth`)
- `key_id` text (`v1`)
- `nonce` bytea (12 random bytes per write)
- `tag` bytea
- `ciphertext` bytea
- `created_at`, `updated_at`

Unique `(kind, account)`. Index `(tenant_id, kind)`.

Table rows use `pending` | `live` | `error` | `needs_reauth` only. Fixture seeds may keep `isolated` / `added` / `watching` until that same `(kind, account)` is replaced by a table row.

Envelope: AES-256-GCM. Fresh 12-byte nonce every write, including refresh-token rotation. AAD = `id|tenantId|kind`. Key = `STATION_MASTER_KEY`: 32 raw bytes, or 64-char hex decoded to 32 bytes. Production already requires the env var. Test/dev keys that are not 32 bytes stay a labeled exception in T5; T15 uses a 32-byte test key.

Plaintext JSON inside the envelope (never logged, never returned on GET):

- email OAuth: `{ transport: "gmail", refreshToken, accessToken?, expiry? }`
- email paste: `{ transport: "imap", imapHost, imapPort, imapTls, imapUser, imapPass, smtpHost, smtpPort, smtpTls, smtpUser, smtpPass }` (default STARTTLS on 587, implicit TLS on 465)
- slack: `{ botToken, workspaceId }`
- obsidian: `{ vaultPath }`
- db: `{ url }` (always read-only in producers; reject writes)
- mcp: `{ name, command, args }`

GET `/connections` returns `{ id, kind, account, label, status, createdAt }` only. A test fails if the JSON or cockpit HTML contains `refreshToken`, `accessToken`, `imapPass`, `smtpPass`, `botToken`, `Bearer`, or `STATION_MASTER_KEY`.

### Forms

| Kind | Fields | Sign in |
| --- | --- | --- |
| email | optional `label`. Paste: imapHost, imapPort, imapTls, imapUser, imapPass, smtpHost, smtpPort, smtpTls, smtpUser, smtpPass | Google |
| slack | label, workspaceId, botToken | no this ticket |
| obsidian | label, vaultPath | no |
| db | label, url | no |
| mcp | label, name, command, args[] | no |

Action sources = the source list on `/`.

Worker derives `account` and ignores a client `account`. Email paste: `imapUser`. Email OAuth: Gmail profile email. Slack: `workspaceId`. Obsidian: `vaultPath`. db: `label`. MCP: `name`. `label` is display only.

### OAuth (email)

1. `GET /oauth/google/start` on the cockpit → worker. Worker stores `state` + PKCE verifier in an in-memory Map with a short TTL (no table). Miss → `auth.oauth_state`. Redirects the browser to Google with `access_type=offline` and `prompt=consent`.
2. Google redirects to cockpit `GET /oauth/google/callback?code&state`.
3. Worker verifies state, exchanges code, calls Gmail `users.getProfile` only (no extra userinfo scope), sets `account` to that email.
4. Encrypts the refresh token (new nonce). Sets status `live` after a profile GET (not a send).
5. On refresh, persist any new refresh token Google returns. Rewrite nonce/tag/ciphertext.

Scopes: `gmail.readonly` + `gmail.send` (restricted; Testing-mode refresh tokens die in 7 days. This ticket writes that into FIRST_RUN. Accept it for first installs.)

### Live email path

`packages/channels` `useEmailConnection(account)`: load row, decrypt, build a transport, drop plaintext after the call.

- OAuth row: Gmail API `users.messages.list` to poll, `users.messages.send` on Approve. Not password SMTP.
- Paste row: IMAP LOGIN (port + TLS required) to poll, SMTP AUTH to send.

Do not change the T11 `commitSend(draft, transport)` signature. Persist `account` on the parked decision from the producing connection. Approve loads that envelope, builds a Gmail or SMTP transport, then calls existing `commitSend(draft, transport)`. Fixture SMTP env is only used when that `(kind, account)` has no live row.

`needs_reauth` is written on Google `invalid_grant` / refresh failure, or IMAP AUTH failure after a row was `live`. `/test` after a successful re-auth returns `live`.

### Worker routes

- `GET /connections`
- `POST /connections` — validate paste only, encrypt, upsert, keep `id`, status `pending`. Cockpit Save for paste kinds then calls `POST /connections/:id/test`. Happy path is `live` or the shown error. Do not leave `pending` after a successful Save.
- `POST /connections/:id/test` — decrypt once, ping, `live` or `error`. OAuth ping: Gmail profile GET. Paste ping: IMAP LOGIN and SMTP AUTH/EHLO (no DATA, no `RCPT`). Slack `auth.test`, `fs.access` vault, `SELECT 1` on db, MCP initialize. Never SMTP DATA / Gmail send.
- `DELETE /connections/:id` — drop row. Parked drafts stay parked. Approve against a missing connection returns `connections.missing` and stays parked.
- `GET /oauth/google/start`, worker-side callback handler (invoked only via cockpit proxy)

Error codes (each needs a client-JSON test): `connections.invalid`, `connections.encrypt_failed`, `connections.decrypt_failed`, `connections.missing`, `connections.needs_reauth`, `auth.oauth_state`.

OAuth callback after profile ping may set `live` without a separate `/test`. Paste Save stays `pending` until `/test` succeeds.

### Seed vs live

Skip a `station.config.ts` seed only when a live row exists for that same `(kind, account)`. Other seeds stay until replaced. Adding one live Gmail must not hide `hello@acme.com`.

Cockpit `connections()` today reads config. Change it to GET `/connections` merged with remaining seeds (JSON `workerFetch`, same as park list). OAuth start/callback stay the dedicated 302 routes above.

### Disconnect and park

DELETE does not kill parked drafts. Approve with a deleted or `needs_reauth` mailbox returns `connections.missing` or `connections.needs_reauth`, state stays `parked`.

### Security rules (tests)

T15 `tests/tickets/T15-connections.test.ts` and `evals/suites/connections.add-source.eval.ts` (`gate: merge`):

- Encrypt/decrypt round-trip with a 32-byte key.
- AAD swap throws `StationError`.
- GET list and cockpit HTML never contain secrets or the master key.
- Two email connections: two `tenantId`s (`account`). Isolation hook: tenant A's prompt has none of B's addresses.
- Approve still does not let the model call `commit_send`.
- Failed `commitSend` stays parked.
- OAuth mock: code exchange + profile sets `account`, GET leaks nothing.
