## Problem Statement

Turn the shared PRD (AI Email Command Station and Non-Deterministic Revenue Engine) into a public kit anyone can clone, extend, and customize. The PRD describes one company's sales machine: five inboxes, a deal-closer, discount rules, human approval. The product is the spine those pieces plug into.

Target first user: a builder who already has an inbox-and-tools problem and will fork this weekend.

## PRD: Tools and architecture

This is the product, in one picture and one tool list. Everything below is detail.

```
 accounts (Gmail/IMAP, Slack, Obsidian vault, DB)
              │
              ▼
     producers (in the worker)
              │  append Signal
              ▼
     ./data/ledger.sqlite          ← one writer
              │
              ▼
     Deep Agents loop + pack
       tools below, skill = directives.md
              │
              ▼
     Decision: defer_draft | inaction_drop | escalate
              │
              ▼
     /park  on :19173   (human Approve / Edit / Kill)
              │
              ▼
     channel.commitSend  (email SMTP/Gmail, Slack post)
```

Same worker and cockpit, two ways to run: `pnpm dev` or one OCI image. Local or cloud is volumes and env, not a second architecture.

### Live-path tools (Deep Agents)

| Tool | Who may call it | Side effect |
| --- | --- | --- |
| `read_signal` | model | none. Returns one `Signal` plus pack scores. |
| `search_ledger` | model | none. Tenant-scoped only. |
| `draft_reply` | model | writes `Draft` + `drafted`. Email or Slack. |
| `query_db` | model | none. Read-only pack SQL. |
| `vault_search` / `vault_read` | model | none. Current vault tenant. |
| `mcp_*` | model | whatever the user-attached MCP servers allow. Still tenant-scoped context. |
| `escalate` | model | `DecisionState = escalated`. No send. |
| `drop` | model | `DecisionState = dropped`. No send. |
| `commit_send` | **never the model** | worker only, after cockpit Approve. |

Recorded replay does not call these tools. It runs `normalize → pack.score → draft_reply template → beforePark` with a frozen clock.

### Code, not tools

`pack.score`, `beforePark`, `policy.throttle`, `assertSingleTenant` are TypeScript. The model does not implement isolation or the 24h throttle.

### Architecture rules (the "right" ones)

1. Producers write the ledger. The loop reads the ledger. APIs are not called from the model except through the tools table.
2. The model cannot send. Approve is HTTP to the worker. `commit_send` is worker-owned.
3. One SQLite writer. Cockpit is read-only on the file.
4. One OCI image. Ports 19173 / 19174. Theme is CSS tokens, not a second UI.
5. Deep Agents is the harness. Packs are the customize surface. Channels are plugins.

## What Makes This Cool

Swap a pack, the station becomes theirs. Risky sends park in the open. Learning is proposed directive diffs, not a mystery blob. Ranked inaction plus re-score under a new objective, on LangChain Deep Agents.

## Constraints

- Open source. Clone, extend, customize is the success condition.
- Config lists for email accounts are unbounded. One worker supports 25 live mail producers. A second worker is out of v1 (one SQLite writer).
- Day-one *code* ships email, Slack, Obsidian, DB, and MCP. Slack/Obsidian/DB/MCP live paths are documented experimental. Email live path is supported.
- Connect to the user's existing accounts. No new mailbox product. Each forker registers their own cloud apps. No shared public OAuth client.
- Docs ship with the code.
- Runtime is LangChain Deep Agents (JS). Not Vercel Eve.
- Cockpit look is a theme, not a fork. CSS tokens plus an optional `theme.css` per pack or per install.
- One OCI image is the runtime. Same image locally (Compose) and in the cloud (Fly, Railway, Cloud Run, or any Docker host). Host paths (vault, tokens, data) are volumes.
- Public name is unresolved. Paths use placeholder `station-kit/`. Do not publish as `frdel/agent-zero`.

## Premises

1. Product is a forkable station kit, not a 600-tool mega-agent and not a five-inbox sales SaaS.
2. `packs/sales` is Example A. `packs/inbox-triage` ships so customize is visible.
3. First park in 20 minutes is a committed fixture. Live Gmail or IMAP is the second path.
4. Mail day-one = Gmail API or IMAP (personal Outlook if IMAP works). Work/O365 Graph is backlog. Slack/Obsidian/DB/MCP adapters ship with fixtures; live is experimental.
5. Clone a public GitHub repo. Docs ship with the code.
6. Deep Agents is the harness. This repo is the station kit on top.
7. The cockpit is restyleable. A forker changes tokens or drops in `theme.css` without rewriting React.
8. Package and run as a container. Local laptop and a cloud VM are the same image, different volumes and env.

## Glossary

- `ProducerRef` — `{ kind: "email" | "slack" | "obsidian" | "db" | "mcp", id: string }`.
- `tenantId` — isolation boundary. Default: email `id` is the mailbox, Slack `id` is the workspace, Obsidian `id` is the vault path. A pack may opt into a `workspace` tenant that lists several `ProducerRef`s (sales closer across inboxes). Prompts never mix tenants unless that opt-in is set.
- `packId` — `sales` or `inbox-triage`. Lives on scores and decisions, never on signals.
- `ledger` — `./data/ledger.sqlite`. One writer: the worker.
- `fixture` — committed JSONL under `fixtures/`.

## Recommended Approach

### Types (`packages/contract`)

```ts
type ProducerKind = "email" | "slack" | "obsidian" | "db" | "mcp"
type ProducerRef = { kind: ProducerKind; id: string }
type TenantId = string
type PackId = "sales" | "inbox-triage"

type Signal = {
  id: string
  tenantId: TenantId
  producer: ProducerRef
  source: ProducerKind
  payload: Record<string, unknown>
  receivedAt: string // ISO
  fixtureId?: string
}

type CandidateLabel = "defer_draft" | "inaction_drop" | "escalate"
type Score = {
  signalId: string
  packId: PackId
  label: CandidateLabel
  value: number
  reasons: string[]
}

type DecisionState = "drafted" | "parked" | "escalated" | "approved" | "rejected" | "sent" | "dropped"
type Decision = {
  id: string
  signalId: string
  tenantId: TenantId
  packId: PackId
  state: DecisionState
  draftId?: string
}

type Draft = {
  id: string
  tenantId: TenantId
  producer: ProducerRef
  kind: "email" | "slack"
  to: string
  body: string
  extra?: Record<string, unknown>
}

type Receipt = { providerId: string; sentAt: string }
type Health = { ok: boolean; detail?: string }
type StopFn = () => Promise<void>

type AccountConfig = {
  producer: ProducerRef
  tenantId: TenantId
  transport?: "gmail" | "imap"
  credentialsKey: string // filename under ./data/tokens/
}

type Channel = {
  startProducer(account: AccountConfig, write: (s: Signal) => Promise<void>): Promise<StopFn>
  normalizeSignal(raw: unknown): Signal
  healthCheck(ref: ProducerRef): Promise<Health>
  toFixture(signal: Signal): string
  commitSend(draft: Draft): Promise<Receipt> // email/slack; others throw unsupported
}

type Pack = {
  id: PackId
  objective: string
  roles: string[]
  score(signal: Signal, ctx: { tenantId: TenantId; pack: Pack }): Score[]
  beforePark(draft: Draft, ctx: { tenantId: TenantId; pack: Pack }): "park" | "escalate" | "drop"
}

type Outcome = {
  decisionId: string
  kind: "sent" | "killed" | "human_label" | "vault_note"
  note?: string
}
```

Load order: `packages/policy` (`throttle`, `assertSingleTenant`) then `pack.beforePark` then model skill `directives.md`. Policy wins.

`packs/sales/intercepts` implements discount floor and $50k via `beforePark`. Inbox-triage does not import those.

### Ledger (SQLite, one writer)

`signals(id PK, tenantId, producer_kind, producer_id, source, payload_json, receivedAt, fixtureId NULL)`
`scores(id PK, signalId FK, packId, label, value, reasons_json, createdAt)`
`decisions(id PK, signalId FK, tenantId, packId, state, draftId NULL, createdAt)` unique latest via `signalId + createdAt` (query `ORDER BY createdAt DESC LIMIT 1`)
`drafts(id PK, tenantId, producer_kind, producer_id, kind, to_addr, body, extra_json, path)`
`outcomes(id PK, decisionId FK, kind, note, createdAt)`
`traces(id PK, signalId, lines_json, createdAt)`

Indexes: `(signals.tenantId, receivedAt)`, `(signals.fixtureId)`, `(decisions.signalId, createdAt)`.

### Process graph

One worker process owns producers, the Deep Agents loop, and an HTTP control port **`:19174`**.
Cockpit (Next.js **`:19173`**) reads SQLite; all writes go through `POST /park/:decisionId/{approve|edit|kill}` on the worker.
These ports are fixed defaults because 3000, 5173, 8000, 8080, and 8787 are usually taken. Override with `STATION_COCKPIT_PORT` and `STATION_WORKER_PORT`. Document both in every environment checklist.
No second writer. No second worker. Postgres is out of v1.

The published artifact is one OCI image (`station-kit:worker` can be the same process supervisor that starts worker + cockpit). Compose for local. The same image on a cloud host. Volumes: `/data` (ledger, tokens, outbox, checkpoints), optional `/vault` for Obsidian. Cloud installs that have no local vault omit the mount; Obsidian is then fixture-only or a remote notes MCP. OAuth loopback on cloud needs a documented redirect URL on the forker's own Google/Azure app.

Loop: read new signals for one `tenantId` → `pack.score` → `beforePark` → write `drafted` then immediately `parked` or `escalated` or `dropped`. Never `drafted → sent` in the scoring turn.

Approve path: cockpit → worker `POST /park/:id/approve` → worker calls `channel.commitSend(draft)` → `sent` + `outcomes`. Deep Agents does not need a cross-process resume. Checkpointer (Deep Agents default SQLite under `./data/checkpoints/`) is for long scoring turns only, not for send.

Tokens: `./data/tokens/{credentialsKey}.json` mode 0600. AES-256-GCM with `./data/master.key`. Desktop/loopback OAuth. Env: `GOOGLE_OAUTH_CLIENT_ID`, IMAP user/pass in the token file. Refresh is the email channel's job.

Producer crash: `startProducer` rejects; worker logs, marks health bad, does not take down other producers. SQLite busy: worker retries writes 5 times.

Isolation test: loop test hook `onPromptBuild(payload)` writes the prompt to a buffer. Fixture tenants A and B; assert A's buffer has none of B's addresses or body.

### Replay

Fixture JSONL line: `{ "signal": Signal, "recordedScores": Score[], "recordedDecision": { "state": "parked", "draftBody": "..." } }`.
Compare in `--mode recorded`: `state`, `draftBody`, `tenantId` only. Clocks frozen to `2026-01-01T00:00:00Z`.
`--mode live` calls the model. Not a merge gate.

### HITL

`drafted → parked | escalated → approved | rejected → sent | dropped`
Cockpit: Approve / Edit (new body, stay parked) / Kill.
Draft files: `./data/outbox/{tenantId}/{draftId}.md`.

Throttle: `packages/policy` key `(producer.kind, producer.id, recipient)` over 24h, email and Slack. Pack may export a stricter window.

### Channels

- Email (supported live): Gmail API or IMAP. `commitSend` via Gmail send or SMTP.
- Slack (experimental live): Socket Mode. `commitSend` posts to a thread.
- Obsidian (experimental live): `chokidar` on the vault path. `commitSend` throws `unsupported`.
- DB (experimental live): read-only SQL from `packs/<id>/queries/*.sql` via `pg` or `better-sqlite3`. No writes. No Prisma.
- MCP (tools only, not a producer): extra tools on that tenant's turn. No outbound MCP server in v1.

### Cockpit routes and theme

`/park` `/accounts` `/packs`. `/traces/:id` is v1.1.
Wireframe of the default layout: `docs/designs/cockpit-sketch.png`.

Look is not hardcoded. Load order:
1. `apps/cockpit/styles/tokens.css` — color, type, space, radius, density.
2. `station.theme.css` at the install root, if present.
3. `packs/<packId>/theme.css`, if present, when that pack is active.

Tokens are CSS variables (`--bg`, `--ink`, `--line`, `--park-border`, `--mono`). A forker restyles the park queue without touching TSX. Pack themes may change accent only; they must not hide Approve / Edit / Kill. Document the token list in `docs/THEMING.md`. Ship two example themes (`default`, `high-contrast`) so customize is visible the same way two packs are.

`DEPLOY.md` environments (each is a copy-paste checklist, not a paragraph):

1. **Local pnpm** — Node 22+, `pnpm i`, `cp .env.example .env`, `pnpm dev`. Open `http://127.0.0.1:19173`. Needs: nothing else.
2. **Local Compose** — Docker 24+. `docker compose up`. Volumes `./data:/data`. Same URL. Needs: Docker only.
3. **Generic Linux VM** — Docker, a public hostname, TLS terminator (Caddy or Caddy in Compose). Needs: DNS A record, ports 80/443, `/data` disk, OAuth redirect `https://<host>/oauth/google/callback` on the forker's Google/Azure app.
4. **Fly.io** — `fly launch` from the provided `fly.toml`. Needs: Fly account, volume for `/data`, secrets (`GOOGLE_OAUTH_CLIENT_ID`, model key), redirect URL.
5. **Railway** — one service from the Dockerfile. Needs: Railway account, volume, the same secrets and redirect.
6. **Cloud Run** — image from GHCR, `--port 19173`, mounted volume or GCS-backed `/data` (if volume is unavailable, SQLite-on-Cloud-Run is a documented limitation: use a small VM instead). Needs: GCP project, Artifact Registry/GHCR pull, secrets, redirect.

Every checklist starts with the same six boxes: [ ] image or `pnpm`, [ ] `/data` writable, [ ] model API key, [ ] ports 19173/19174 or env overrides, [ ] OAuth client redirect matches this host (skip on fixture-only), [ ] open `/park` and see the demo fixture.

`.env.example` lists every variable. If a variable is not in that file, it does not exist.
