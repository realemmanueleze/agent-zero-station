## Problem Statement

`/channels` is a kind roster with no Add. `/channels/email` already has Add source, but it is a six-field IMAP form with Sign in with Google as a quiet pill. After a live demo the operator named both URLs: email should add mailboxes; Channels should add a source and let them pick the type.

## Demand Evidence

Quote from the demo turn: "`/channels/email` should allow us add emails, `/channels` should have add source and we can select what type of source." The live page at `/channels` has no add control. The live email panel shows IMAP host/user/password and SMTP host/user/password on first paint.

## Status Quo

T15 vault is live: `POST /api/connections`, `/test`, Nango or station OAuth, encrypted ledger rows. `AddSourcePanel` mounts only on `/channels/[kind]`. `ChannelsIndex` is a list. Connecting never sends. Approve still owns send.

Nango Sign in is not a return-to-desk 302. Cockpit `GET /nango/start` 302s to Nango Connect. The vault row appears when `POST /api/nango/import` runs (today: `visibilitychange` on `AddSourcePanel`). Station Google OAuth is the path that 302s to `/channels/email/{id}`. Slack OAuth 302s to `/channels/slack/{id}` on success. Start 4xx becomes `oauthFailureHtml` with a "Back to email" link.

## Target User & Narrowest Wedge

Clone operator adding a second Gmail from the desk, not from `.env`. Wedge: two doors, one ConnectFlow rail, Google-first email.

## Constraints

- Vault, Nango, paste, and `/test` stay. No new connect stack.
- Throw only `StationError`. Log only through `@station/observability`. Redact secrets.
- Connecting never sends. Model tools never include `commit_send`.
- Copper stays on Approve / Edit / Kill and the Action waiting chip. Add is a quiet pill. Sign in keeps the existing `quiet-pill` tint for `href` containing `oauth` or `nango` in `globals.css` (primary connect, not HITL).
- Tests and evals before program code. T32+ stays out of scope.
- `docs/DESIGN.md`: command desk, small titles, no kicker labels, kind-layout already 1fr / 22rem. Every desk surface has named loading / empty / error / ready. Errors use `role="alert"`.

## Premises

1. Build on T15. UX recut only.
2. `/channels` gets Add source that asks what kind, then runs that kind's connect. The picker does not navigate. Sign in may leave the app. Paste and Nango-import success assign `/channels/{kind}/{id}`.
3. `/channels/email` is mailbox-first: Add email, not a generic source form.
4. Email first paint is Sign in with Google. IMAP/SMTP is a disclosure.
5. Connecting never sends.

## Approaches Considered

### Approach A: Same panel, two entries
Add source on `/channels` navigates to `/channels/{kind}?add=1`. Ruled out: the index never actually connects.

### Approach B: One ConnectFlow rail
Chosen. Shared right rail on both URLs. Kind unknown → picker. Kind known → that kind's method. No `?add=` query param.

### Approach C: Kind cards plus ⌘K
Ruled out: splits the habit and hides Add from first-run clones who do not know ⌘K.

## Recommended Approach

One `ConnectFlow` client component. Same 22rem right rail as today's Add source panel, not a modal. Props: `kind?: ChannelKind`. Local UI state `step` (`kind` | `method` | `imap`). Index omits `kind` and starts at the picker. Kind pages pass `kind` and skip the picker. No URL writes until a success navigation.

```
/channels                    kind omitted, step=kind
   pick email                step=method, still /channels
   Sign in with Google       browser leaves (Nango replace, or station OAuth)
   or IMAP Add               POST paste + /test → assign /channels/email/{id}

/channels/email              kind=email, step=method
   same Google / IMAP        success → /channels/email/{id}

/channels pick slack         kind=slack, Sign in + workspace + token fields
obsidian / db / mcp          existing fields + Add
```

Email is the only kind whose form is recut this ticket. Other kinds keep today's fields so the index picker has somewhere to land. Slack-token disclosure is deferred. Slack **Sign-in return** (deny / start 4xx / Nango Back) is in this PR (eng D6 C).

### Email paste contract

Visible after disclosure (same fields in the prototype scene 4):

- Email → `imapUser` and `smtpUser`
- Password → `imapPass` and `smtpPass`
- SMTP host, default `smtp.gmail.com`
- IMAP host, default `imap.gmail.com` (same disclosure, not a second Advanced layer)

Hidden defaults: `imapPort=993`, `imapTls=true`, `smtpPort=587`, `smtpTls=true`.

No separate SMTP password field. No automatic non-Gmail detection.

Red test: that four-field submit 200s `POST /api/connections` with both user fields and both password fields filled from Email + Password.

`POST` still creates `pending`. Same-email paste already upserts by `imapUser` and returns the same id. Retry may POST again (so a corrected Password is stored), then `/test`. Do not skip POST. Hold `pendingId` only to detect a different Email creating a new row. On `/test` failure: `router.refresh()` so the roster shows `error`, and `role="alert"` "testing login failed" (or `error.message`) under Add.

### Sign in return (three paths)

Port today's `visibilitychange` → `POST /api/nango/import` onto `ConnectFlow`. Also listen to `pageshow` so a bfcache Back still imports.

```
                 ┌─────────────────────────────────────────┐
                 │ ConnectFlow on door                     │
                 │ /channels  or  /channels/{kind}         │
                 └───────────────┬─────────────────────────┘
                                 │
            snapshot ids → sessionStorage.station.connect.ids
                                 │
              ┌──────────────────┼──────────────────┐
              │                  │                  │
              ▼                  ▼                  ▼
        Path 1 Nango        Path 2 station     Path 3 start 4xx
        Sign in click       OAuth <a>          or provider deny
              │                  │                  │
              ▼                  ▼                  ▼
     POST /api/nango/     GET /oauth/{google,  worker 302 Location
     session              slack}/start?return=  {origin}{door}?connect=error
              │                  │
              ▼                  ▼
     location.replace     PKCE map stores
     (connectLink)        return + verifier
              │                  │
              ▼                  ▼
     Back = door          success 302
     pageshow → import    /channels/{kind}/{id}
     new id → assign      deny/error 302
                          {origin}{stored return}?connect=error
```

**Path 1 — Nango (eng D5 A).** Sign in is a `button`, not a same-tab `<a href="/nango/start">`. Snapshot ids, strip `?connect=error` with `history.replaceState` so a prior fail does not poison retry, `POST /api/nango/session` with `{ kind }`, then `location.replace(connectLink)`. Back lands on the door; ConnectFlow is still mounted; import can run. Bookmark `GET /nango/start?kind=&return=` stays for no-JS; worker still 302s to Nango Connect.

**Path 2 — station Google / Slack.** `<a href="/oauth/google/start?return=…">` or `/oauth/slack/start?return=…`. Cockpit start routes forward `return` blindly. Worker `returnPath()` allowlists it and stores it on the PKCE entry at `start()`. Success still 302s to `/channels/email/{id}` or `/channels/slack/{id}` (ignore stored return). `ConnectionView` clears `station.connect.ids` on mount so a leftover snapshot cannot fire a false "new id" later.

**Path 3 — start 4xx or deny.** Worker does not throw JSON for these handlers. Missing client id, Nango session fail, empty code, `error=` query, or expired PKCE → `302` to `{allowedOrigin}{returnPath}?connect=error`. Cockpit start/callback routes only forward `Location`. If the worker is down, cockpit 302s to the fixed path `/channels?connect=error` (do not trust the request's `return=` when the worker cannot validate). Keep `oauthFailureHtml` only for unexpected non-OAuth worker errors.

`sessionStorage` holds connection-id snapshot only (`station.connect.ids`), never the door.

On Sign in click, snapshot current ids. After import: `GET /api/connections`. If a new id appeared, `location.assign(/channels/{kind}/{id})` and clear the snapshot. If `?connect=error` is present, clear the snapshot, show `role="alert"` "Sign in didn't finish. Try again.", and do not treat a missing new id as a second alert. If there is no snapshot (ordinary tab focus), import stays fire-and-forget.

